# 6.0.2 — устранение конфликта старого и нового HTTP-сервера

Пользователь сообщил: новая консоль показывает 6.0.1, но браузер на том же порту — интерфейс 5.2. GET /api/runtime возвращал 404, что устанавливает отсутствие API новой копии у отвечающего сервера.

Стандартный HTTPServer включает SO_REUSEADDR. На Windows это допускает повторную привязку занятого адреса с неопределённым распределением запросов. Это согласуется с наблюдением; нативно Windows в среде разработки недоступна, поэтому причину на компьютере пользователя пока не воспроизвели.

Исправления:

- SO_REUSEADDR и SO_REUSEPORT отключены; на Windows перед bind устанавливается SO_EXCLUSIVEADDRUSE.
- Desktop по умолчанию запрашивает свободный порт у ОС (port=0), вместо использования старого 8765.
- Перед запуском браузера HTTP-запрос /api/runtime должен вернуть точные version и случайный instance_id этой копии. При 404, чужом ответе или ошибке проверка прерывает запуск и закрывает только собственный сервер.
- Браузер открывает уникальный /launch/<instance_id>, с no-store и заголовками версии/идентификатора.
- Контрольный SHA-256-манифест исходников и лаунчеров обнаруживает неполную или смешанную распаковку. Пользовательские данные и настраиваемые JSON-справочники не проверяются.

Проверки: занятый порт, Windows-порядок socket options через mock, отбрасывание 404/чужого идентификатора, запрет открытия браузера при ошибке проверки, реальные локальные HTTP-запросы и запуск Chromium на проверенном URL.
