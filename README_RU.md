# ThreatWatch Global v5.1 — запуск без терминала

**Главный файл для Windows:** дважды щёлкни `START_THREATWATCH.bat` в распакованной папке.

При наличии Python 3.11+ приложение само проверит две необходимые зависимости (`truststore`, `certifi`), откроет браузер на `http://127.0.0.1:8765/control`, начнёт сбор публичных данных **без ИИ** и включит расписание раз в 6 часов. Пока работает, окно терминала можно свернуть, но не закрывать. Закрытие окна прекращает веб-сервер и автоматические запуски. Если браузер не открылся сам, открой адрес вручную.

**Как обновиться с v5 без потери данных:** останови старое приложение, сделай копию старого `data\threatwatch.db`, распакуй v5.1 в **новую** папку и перенеси копию базы в её `data\threatwatch.db`. Не копируй файл при работающей программе: сначала останови её, чтобы не потерять данные из SQLite WAL. Исходная база, присланная в чат, **не вложена** в скачиваемый ZIP.

Теперь основные действия в браузере:

- **Управление** (`/control`): собрать сейчас, поставить/убрать расписание, посмотреть ошибки и скачать CSV;
- **Кандидаты** (`/candidates`): открыть кандидата, сверить ссылку, утвердить организацию (страна ISO-2 + отрасль) либо отклонить ошибку распознавания;
- **Разметка** (`/audit`): создать очередь из 80 статей, проверить упомянутые организации по оригиналу, получить precision/recall/F1;
- **Источники** (`/sources`): посмотреть, какие внешние RSS/API отвечают;
- **Статистика** (`/analytics`) и **Граф** (`/graph`): исследовать накопленные сведения, не считая заявления групп подтверждёнными взломами.

**Если GDELT отвечает `429`:** система не пытается обходить лимит. После ошибки следующие запросы GDELT откладываются; повторная попытка не раньше чем через шесть часов. Если русский Securelist не отвечает по SSL, он сейчас выключен в `sources.json`; английский остаётся включённым. Если нужен русский, можешь самостоятельно включить источник позже. Не отключай проверку TLS.

**ИИ только по желанию:** двойной клик и кнопки в панели не включают Ollama/OpenAI. Ручной запуск `python -m threatwatch run --local-ai` по-прежнему доступен. Киберинциденты, связи и риск должны проверяться по источникам; ИИ не является подтверждающим свидетельством.

**Качество модели:** пока в предоставленной базе только один день наблюдений, исторические прогнозы за 14 дней невалидны. Пустые оценки у большинства 16 исходных организаций не ошибка в расчётах; множество данных находится в очереди из 373 кандидатов. Используй разметку и проверку организаций прежде, чем пытаться калибровать вероятность взлома.

# ThreatWatch Global v5.0 — установка и новые возможности

**Статус:** локальный исследовательский прототип для defensive OSINT. ИИ **необязателен** и по умолчанию выключен. Сборщик не сканирует инфраструктуру организаций, не проверяет учётные записи и не загружает украденные данные. Индекс мониторинга **не является вероятностью взлома**.

## A. Как перейти с v4, сохранив настоящую базу

1. Остановите `watch` и `serve` в старой папке. Сделайте **резервную копию** файла `data\threatwatch.db` (вместе с `-wal` и `-shm`, если они появились при открытой базе; безопаснее сначала остановить процессы).
2. Распакуйте архив v5 в новую папку. Скопируйте сохранённую `data\threatwatch.db` в `data\` новой папки. **Не заменяйте файл на демобазу.**
3. В CMD или PowerShell из папки v5:

```bat
python -m pip install -r requirements.txt
python -m threatwatch init
python -m threatwatch doctor
python -m threatwatch run
python -m threatwatch serve
```

Откройте `http://127.0.0.1:8765/`. Два новых раздела — **«Граф связей»** (`/graph`) и **«Качество»** (`/quality`). Существующий сбор каждые шесть часов: `python -m threatwatch watch --every-hours 6`.

При обновлении v4 → v5 в SQLite добавляются `mentions.linked_at` и `entity_candidates.reviewed_at`. **Историческая дата ранних связей неизвестна**. Для безопасной проверки задним числом их первая доказуемая дата в v5 — момент миграции. Старые публикации остаются доступны для текущего анализа, но не должны использоваться как будто их связи были известны несколько месяцев назад.

## B. Проверка качества обнаружения компаний — первый практический шаг

```bat
python -m threatwatch discover-entities
python -m threatwatch export-entity-audit exports\entity_review.csv --size 100 --seed 42
```

Откройте CSV в Excel или LibreOffice. Для каждой статьи, которую вы действительно проверили, заполните:

- `reviewed`: `yes`
- `expected_organizations`: **все** действительно упомянутые в статье организации, разделённые символом `|`; укажите `NONE`, если их нет
- `reviewer_notes`: по желанию, пояснение расхождений

Не копируйте `predicted_organizations` без проверки. В выборке специально есть статьи, в которых программа ничего не нашла — без них нельзя оценить **полноту**. По возможности единообразно пишите полные названия, чтобы не считать `EDF` и `Électricité de France` двумя разными компаниями. Используйте одни и те же правила написания в эталонных и предсказанных названиях.

После разметки:

```bat
python -m threatwatch evaluate-entity-audit exports\entity_review.csv
```

Появятся `precision` (доля правильных среди найденных), `recall` (доля найденных среди всех названий по ручной разметке), `F1` и список конкретных ошибок. **Непроверенная статья не становится отрицательным примером.** Результат относится к контрольной выборке статей, а не к точности прогноза взломов. Для достоверных выводов лучше проверить не меньше 100–200 репрезентативных материалов из разных источников.

## C. Граф документированных связей

Для просмотра:

```bat
python -m threatwatch graph-context edf
python -m threatwatch graph-context edf --as-of 2026-10-29
```

На `/graph` можно фильтровать организации по стране/отрасли, выбирать историческую дату, просматривать подтверждённые отношения и примеры косвенной активности. В диаграмму попадают **только проверенные отношения**; источники смотрите в таблице под ней. В базу они вносятся через `relations_template.csv` и команду `import-relations` (см. ниже старую документацию v4).

Отдельно показаны четыре индикатора с диапазоном 0–5: количество документированных соседей, количество публичных сообщений о соседях за 14 дней, о других организациях той же отрасли и той же страны. Для исторических срезов учитываются только записи, опубликованные, полученные и связанные с организацией **не позднее даты среза**. Само отношение также должно быть проверено и зарегистрировано до этой даты.

**Не путайте** эти числа с вероятностью атаки: связь с организацией, упомянутой в публикации, не делает другую компанию жертвой; принадлежность к одной стране — не техническая зависимость.

## D. Проверка графовых признаков на исторических данных

```bat
python -m threatwatch history-status
python -m threatwatch prepare-graph-history exports\graph_unlabelled.csv
```

Программа строит лишь те срезы, для которых есть **28 дней реального мониторинга** на дату оценки, а затем полностью истекли следующие **14 дней**. Срезы экспортируются со статусом `UNLABELLED_REQUIRES_INDEPENDENT_REVIEW`. Если настоящей базы ещё мало, появится `insufficient_historical_coverage` и CSV с одной строкой-заголовком. Это ожидаемо, не ошибка.

Для каждой строки при независимой проверке заполните `incident_next_14d`: `1` — подтверждён конкретный инцидент в последующие 14 дней, `0` — достаточное основание считать, что наблюдение не выявило такого события; не используйте `0` только потому, что не видели новостей. Укажите `label_status=verified` и независимую HTTPS-ссылку `outcome_evidence_url`. Этот эксперимент **не заменяет** реальный мониторинг отрицательных исходов: для надёжной модели требуется последовательный список компаний под наблюдением и правила подтверждения отсутствия события.

```bat
python -m threatwatch validate-graph exports\graph_verified.csv
```

Сравниваются **одни и те же исторические примеры** в двух вариантах: 8 прямых признаков и 8+4 графовых. Разделение по времени с **14-дневным разрывом** препятствует смешению горизонтов прогноза. Отчёт выводит Brier score для обеих моделей и постоянного baseline, показатели калибровки, долю событий и объёмы выборок. Малый Brier **лучше**, но сам по себе не подтверждает работающий прогноз для конкретной компании. В реальной выборке нужны достаточно длинная история, качественные положительные/отрицательные исходы и внешний контроль.

ИИ для этих расчётов не нужен: математическая проверка работает на стандартной библиотеке Python. Ollama может помогать извлекать имена и делать текстовые выжимки, но не подменяет независимую проверку фактов.

## E. Что пока не сделано

- Нет обученной на настоящих подтверждённых исходах модели вероятности будущего взлома: в архив **не включена база с вашего компьютера**, а модель не может создавать реальные исходы самостоятельно.
- Графовая модель пока строит один шаг документированных отношений; не делает автоматических выводов, что «все соседи пострадавшей компании скоро будут взломаны».
- Внешние API/фиды требуют проверки в вашей сети. Офлайн-тесты не гарантируют, что каждый источник сейчас доступен.

# ThreatWatch v4 — Incident-first OSINT (русская инструкция)

**Релиз:** 4.0, учебная защитная аналитика. Программа работает локально на Windows 10/11, Linux и macOS (Python 3.11+). Не проводит сканирование, проверку уязвимостей, вход на сайты организаций или загрузку утекших данных. Сбор идёт только из открытых RSS, документированных публичных API и разрешённых открытых публикаций.

**Главное изменение:** организация больше не обязана заранее находиться в `organizations.json`. Сначала получаем свежие материалы об инцидентах, затем создаём **кандидатов** на основе явно названных в публикациях организаций. Кандидат — это ещё не подтверждённая жертва или будущая цель. Только аналитик может утвердить организацию для постоянного мониторинга. Исходный список из 16 французских организаций сохранён для совместимости с v3.2; можно менять его, а новые утверждённые организации продолжают храниться в SQLite.

## 1. Обновление с v3.2 без потери данных

1. Остановите старые процессы `run`, `watch` и `serve`.
2. Сохраните резервную копию `data\threatwatch.db` из старой папки.
3. Распакуйте **в новую папку**, а затем скопируйте эту базу в `data\threatwatch.db` новой версии.
4. Запустите в командной строке Windows из папки v4:

```bat
python -m pip install -r requirements.txt
python -m threatwatch init
python -m threatwatch discover-entities
python -m threatwatch run
python -m threatwatch serve
```

Откройте `http://127.0.0.1:8765/`. База мигрируется дополнением таблиц `entity_candidates`, `candidate_evidence`, `organization_relations`. Имеющиеся записи `items`, `discovery`, `scores` остаются на месте. Не смешивайте реальную базу с командой `demo`.

## 2. Новые разделы панели

- **Обзор** (`/`) — итоговые индексы мониторинга с фильтрами **страна / отрасль / наличие данных**.
- **Инциденты** (`/incidents`) — общая лента статей и заявлений, в том числе об организациях, которые ещё не включены в мониторинг; фильтры по стране, отрасли и типу текста.
- **Статистика** (`/analytics`) — агрегаты уникальных ссылок на публикации по известным странам и отраслям организаций, с сохранением `Unknown`.
- **Кандидаты** (`/candidates`) — организации, обнаруженные из структурированных заявлений и некоторых заголовков. Фильтры по стране, отрасли и статусу проверки. Карточка кандидата показывает первичные источники.
- **Карточка организации** (`/org/ID`) — объяснение, ссылки, индекс, отдельно: подтверждённые документами отношения, организации той же страны/отрасли и совместные упоминания.
- **Киберкарта** (`/cybermap`) — прежний официальный виджет Kaspersky и новости Securelist.

Важно: публикация на ransomware-сайте **не означает**, что компрометация подтверждена; страна издателя не означает страну пострадавшей организации; совместное упоминание не означает деловые связи. Оценка 0–40 НЕ является математической вероятностью взлома.

## 3. Международные источники

`source.json` в действительности называется **`sources.json`**; каждый источник включается/выключается через `"enabled": true/false`.

В v4 добавлены: **GDELT DOC 2.0** (публикации глобальных СМИ), дополнительные международные запросы Google News, **Ransomfeed worldwide** (`/offset/300`), **Ransomwhere** (`/api/victims`), The Record. Сохраняются RansomLook, Ransomfeed France, ZATAZ, CERT-FR, 01net, Securelist и прочие. Наборы типа `google_org_search` выключены **по умолчанию**, чтобы не умножать десятки запросов по каждому названию. Любой отдельный API может иметь лимиты, временные ошибки или менять формат; состояние видно на странице «Источники».

Ransomfeed официально ограничивает обращения приблизительно пятью запросами в минуту. Не устанавливайте очень маленький `--delay`, если API отвечает `429`. Зафиксировать работу внешних сервисов можно только запуском в вашей сети; офлайн-тесты проверяют обработку подготовленных ответов, а не живую доступность.

## 4. Обнаружение новых организаций БЕЗ ИИ

После каждого `run` программа автоматически пополняет таблицу кандидатов. Для уже сохранённой базы выполните:

```bat
python -m threatwatch discover-entities
python -m threatwatch entities --status pending --limit 30
python -m threatwatch entities --country FR
python -m threatwatch entities --sector Healthcare
```

В систему кандидатов попадают названия, явно указанные в структурированном поле `Ransomware claim: <имя>`, в вручную размеченной карточке или в ограниченном наборе газетных заголовков. Остальные статьи сохраняются для изучения; нет гарантии обнаружить каждую организацию. Указанные в лентах страна/отрасль считаются **непроверенными метаданными**, пока вы их не сверили.

После проверки конкретной записи можно добавить организацию в мониторинг:

```bat
python -m threatwatch approve-entity 12 --country FR --sector healthcare
```

Число `12` — пример ID из команды `entities`. Команда напечатает реальный `organization_id`, нужный для ссылок и экспорта. Неверную запись можно отклонить:

```bat
python -m threatwatch reject-entity 12
```

Отклонение не удаляет первичные публикации из базы. Утверждение означает только, что сущность подходит для дальнейшего мониторинга, **не подтверждает факт атаки**. Если для неё ещё мало свидетельств, индекс останется `Н/Д`.

## 5. Связанные организации

Три разных вида связей:

1. **Похожие по стране/отрасли** — вычисляются автоматически из известных классификаций. Это не фактическая связь компаний.
2. **Упомянутые в одной публикации** — вычисляются автоматически из журнала. Это не цепочка атаки и не коммерческие отношения.
3. **Документированные отношения** — parent, subsidiary, supplier, customer, partner и т. д.; только с обязательной URL-ссылкой на источник и статусом ручной проверки.

Для третьей категории заполните `relations_template.csv` и выполните:

```bat
python -m threatwatch import-relations relations_template.csv
python -m threatwatch connections edf
```

Можно попробовать **Wikidata** для поиска публично заявленных родительских и дочерних организаций. Сначала найдите и проверьте точный ID элемента `Q...` на Wikidata, затем:

```bat
python -m threatwatch enrich-wikidata edf Q123
```

Здесь `Q123` — **синтаксический пример**, не корректный идентификатор EDF; подставьте настоящий проверенный QID. Программа откажется автоматически соединять разные имена, а результат маркирует как неподтверждённое предложение. Ограничение: Wikidata может иметь неполные, устаревшие или ошибочные записи. ИИ не доказывает деловые отношения.

## 6. Ручной импорт новой публикации, даже без заранее известной компании

Заполните `incident_import_template.csv`: URL статьи, дата в ISO 8601, заголовок, вид сообщения, имя организации в `candidate_name` только когда оно **явно указано** в первоисточнике. Команда:

```bat
python -m threatwatch import-incidents incident_import_template.csv
```

Информация сохранится в общем журнале и создаст кандидатную организацию. Файл-шаблон поставляется пустым; все дополнительные исследования должны иметь реальные, доступные ссылки.

## 7. ИИ только по желанию

Для стандартной работы Python и SQLite достаточно. Опции ИИ **не включены** автоматически даже при наличии API-ключа или Ollama:

```bat
python -m threatwatch run
python -m threatwatch watch --every-hours 6
```

Для локальной бесплатной модели установите Ollama и скачайте выбранную модель (например, `gemma3:4b`, отдельная загрузка порядка нескольких ГБ). Затем используйте:

```bat
ollama pull gemma3:4b
python -m threatwatch triage-discovery --limit 10
python -m threatwatch discover-entities --include-ai-suggestions
```

Или по желанию после сетевого сбора:

```bat
python -m threatwatch run --local-ai --local-ai-limit 5
```

LLM предлагает имена, но **никогда автоматически не утверждает организации, корпоративные связи или вероятность взлома**. Программная обработка исходных текстов полностью работает без LLM; OpenAI API остаётся альтернативой `--ai` и требует ключ.

## 8. Экспорт и историческая статистика

```bat
python -m threatwatch export entities exports\entities.csv
python -m threatwatch export relations exports\relations.csv
python -m threatwatch export discovery exports\unmatched.csv
python -m threatwatch export evidence exports\evidence.csv
python -m threatwatch history-status
python -m threatwatch prepare-history exports\history_candidates.csv
```

Математический модуль из v3.2 сохранён. Он не обучает вероятность успешного взлома из публикаций, потому что общее число «взломанных компаний» нельзя подставить вместо всех компаний, находившихся под наблюдением. Для корректной модели нужны размеченные подтверждённые исходы, известность признаков **на дату прогноза**, независимые отрицательные исходы и проверка на будущем интервале. Формальные оценки строятся только после такой проверки.

## 9. Проверки и ограничения

```bat
python -m pip install pytest
python -m pytest -q
python -m threatwatch doctor --test-network
```

Тесты преимущественно офлайн. Если источник отдаёт ошибку или временно недоступен, это фиксируется в журнале, а другие источники продолжают работать. Веб-интерфейс по умолчанию слушает **только локальный компьютер**, не нужно открывать его в интернет.

**Важно о дублировании:** Ransomfeed, RansomLook, Ransomwhere и Ransomware.live могут перепечатывать **одно** исходное заявление. Все они относятся к общей группе `ransomware-leak-monitors`, а не считаются независимым подтверждением компрометации.
